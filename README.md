# Rover - Инструкция по аппаратному обеспечению и тестированию

Данный документ содержит полное описание архитектуры прошивки, распиновку для подключения аппаратной части (драйверов DRV8871 и энкодеров) к микроконтроллеру STM32F429ZI, а также инструкцию по диагностике и тестированию системы.

---

## 1. Аппаратное подключение к STM32 
В помощь https://os.mbed.com/platforms/ST-Nucleo-F429ZI/

### 1.1. Драйверы двигателей DRV8871
Каждый из 6 моторов управляется отдельным драйвером DRV8871. Управление осуществляется по двум линиям: `IN1` (ШИМ-сигнал мощности) и `IN2` (логический уровень направления).

**Особенности работы с DRV8871:**
В прошивке реализована специальная логика для исключения состояния аппаратного торможения (Brake), когда на обоих входах драйвера логическая `1`:
- **Движение вперед:** `IN2` (DIR) = 0, `IN1` (PWM) = Прямая скважность от ПИД-регулятора.
- **Движение назад:** `IN2` (DIR) = 1, `IN1` (PWM) = Инвертированная скважность (`MAX_PWM - |мощность|`).

| Мотор | Сторона | Пин IN2 (DIR) | Пин IN1 (PWM) | Таймер и Канал ШИМ |
|-------|---------|---------------|---------------|-------------------|
| **0** | Левая   | **PF0**       | **PE5**       | TIM9_CH1          |
| **1** | Левая   | **PF1**       | **PF6**       | TIM10_CH1         |
| **2** | Левая   | **PF2**       | **PF7**       | TIM11_CH1         |
| **3** | Правая  | **PF3**       | **PB15**      | TIM12_CH2         |
| **4** | Правая  | **PF4**       | **PF8**       | TIM13_CH1         |
| **5** | Правая  | **PF5**       | **PF9**       | TIM14_CH1         |

*💡 Примечание:* Если при команде "вперед" какой-то мотор крутится назад, вы можете либо физически поменять местами силовые провода мотора (рекомендуется), либо программно инвертировать логику для конкретного мотора в `Core/Src/motor.c`.

### 1.2. Аппаратные энкодеры
Для определения текущей скорости и пробега используются квадратурные энкодеры. Выходы фаз A и B подключены напрямую к входам аппаратных таймеров STM32, работающих в режиме аппаратного энкодера.

| Энкодер | Пин Фазы A (CH1) | Пин Фазы B (CH2) | Используемый Таймер |
|---------|------------------|------------------|---------------------|
| **0**   | **PE9**          | **PE11**         | TIM1                |
| **1**   | **PA5**          | **PB3**          | TIM2 (32-bit)       |
| **2**   | **PA6**          | **PB5**          | TIM3                |
| **3**   | **PD12**         | **PD13**         | TIM4                |
| **4**   | **PA0**          | **PA1**          | TIM5 (32-bit)       |
| **5**   | **PC6**          | **PC7**          | TIM8                |

### 1.3. Связь с управляющим компьютером (UART4)
Обмен телеметрией и целевыми командами (Target Speeds) с хостом (например, Orange Pi или Raspberry Pi) происходит по интерфейсу UART с использованием DMA для минимизации нагрузки на процессор. Скорость обмена — **115200 бод**, частота отправки пакетов — 50 Гц (20 мс).

- **PC10 (TX)** -> RX-пин Orange Pi.
- **PC11 (RX)** -> TX-пин Orange Pi.
- **GND** -> **ОБЯЗАТЕЛЬНО** соедините земли (GND) STM32 и Orange Pi вместе.

В системе реализован **Failsafe**: если валидные пакеты от управляющего ПК не приходят более 500 мс, все моторы принудительно останавливаются, чтобы избежать аварии.

## 2. Сборка и Прошивка 

Обновление программного обеспечения микроконтроллера требует перекомпиляции и загрузки новой прошивки:

1. **Сборка проекта:** Скомпилируйте проект в вашей IDE (или через терминал `cmake --build build`). Дождитесь сообщения об успешном завершении сборки.
2. **Прошивка STM32:** Загрузите полученный файл `Rover.elf` / `Rover.bin` через ST-Link с помощью STM32CubeProgrammer или встроенных средств вашей IDE.
3. **Перезагрузка:** Нажмите кнопку **Reset** на микроконтроллере для запуска нового кода.

*(Если не прошить контроллер, плата продолжит выполнять старый код).*

## 3. Управляющий ПК: Зависимости и Установка

Для запуска скрипта тестирования `test_serial.py` и работы ROS 2 пакета `uart_bridge_pkg` на управляющем компьютере (например, Orange Pi 3b) необходимо установить следующие зависимости.

### 3.1. Список зависимостей
* **Системные (ROS 2 Humble):** `rclpy`, `geometry_msgs`, `nav_msgs`, `std_msgs` (поставляются вместе со средой ROS 2).
* **Python-библиотеки:**
  * `pyserial` — обмен данными с STM32 через UART.
  * `Flask` — веб-сервер панели мониторинга.
  * `Flask-SocketIO` — WebSocket-сервер для обновления графиков в реальном времени.

### 3.2. Команды для установки

**Способ 1: Через пакетный менеджер APT (Рекомендуется для Orange Pi / Ubuntu)**
Устанавливает зависимости на системном уровне без конфликтов с PEP 668:
```bash
sudo apt update
sudo apt install python3-serial python3-flask python3-flask-socketio
```

**Способ 2: Через pip**
Если вы используете виртуальное окружение или устанавливаете библиотеки напрямую:
```bash
pip3 install pyserial Flask Flask-SocketIO
```
*Примечание: на современных версиях ОС при попытке глобальной установки pip выдаст ошибку "externally-managed-environment". В этом случае используйте флаг `--break-system-packages`:*
```bash
pip3 install pyserial Flask Flask-SocketIO --break-system-packages
```

### 3.3. Настройка прав доступа к UART-порту
Для доступа к последовательным интерфейсам без прав `sudo` добавьте пользователя в группу `dialout`:
```bash
sudo usermod -a -G dialout $USER
```
*После выполнения команды перезайдите в систему или перезапустите ПК.*

## 4. Тестирование и диагностика (test_serial.py)

Для базовой проверки электроники без необходимости разворачивать ROS2 стек, используйте утилиту `Scripts/test_serial.py`.

### 4.1. Запуск
Подключите управляющий компьютер к STM32 по UART и выполните команду:
```bash
python3 Scripts/test_serial.py
```
*(Убедитесь, что переменная `SERIAL_PORT` в скрипте указывает на правильный порт, например `/dev/ttyS7` или `/dev/ttyUSB0`).*

### 4.2. Порядок проверки системы

**Шаг 1. Проверка чтения энкодеров (без моторов)**
1. Запустите скрипт, не подавая команду на скорость (`linear_x = 0`).
2. Вручную вращайте колеса ровера вперед по одному.
3. В консоли должны обновляться данные энкодеров: `[RX] Энкодеры: (15, 0, 0, 0, 0, 0)`.
4. При вращении вперед значения должны **расти** (в плюс), при вращении назад — **уменьшаться** (в минус).
5. *🔧 Исправление:* Если при вращении вперед значение уходит в минус, **поменяйте местами провода фаз A и B** на колодке контроллера для данного мотора.

**Шаг 2. Проверка моторов и ПИД-регулятора**
1. Введите в терминал скрипта тестовую скорость: `linear_x: 0.3` (Enter).
2. Моторы начнут вращаться. ПИД-регулятор внутри STM32 автоматически подберет необходимую мощность ШИМ на основании обратной связи от энкодеров.
3. Попробуйте придержать вращающееся колесо рукой — вы почувствуете увеличение крутящего момента (работа интегральной компоненты ПИД).
4. Введите `linear_x: 0.0` для остановки моторов.

## 5. Частые проблемы и их решение

* **Энкодеры всегда показывают нули:** 
  Убедитесь в наличии питания (3.3V/5V) на энкодерах. Проверьте правильность подключения сигнальных пинов к `TIMx_CH1` и `TIMx_CH2`.

* **Мотор уходит "вразнос" (мгновенно раскручивается до 100% при малой заданной скорости):**
  Возникла положительная обратная связь ПИД-регулятора. Мотор физически крутится вперед, но энкодер инвертирован и считает в минус. ПИД пытается "догнать" целевую скорость, увеличивая мощность ШИМ до максимума.
  **Решение:** Поменяйте местами фазы A и B энкодера ИЛИ поменяйте местами силовые провода мотора (в зависимости от того, куда физически едет колесо).

* **Ошибка CRC (`Ошибка CRC: calc=XX, recv=YY`) в скрипте:**
  Нарушена целостность данных по UART. Убедитесь в надежности контактов, наличии общего GND и, при необходимости, используйте экранированные провода или снизьте скорость (Baud Rate).

* **Пакеты идут без ошибок CRC, но моторы стоят:**
  Проверьте силовое питание (12V/24V) на драйверах DRV8871. Убедитесь, что силовая земля (GND) батареи объединена с сигнальной GND STM32. С помощью осциллографа или мультиметра проверьте уровни на пинах `IN2` (DIR, PF0-PF5) и наличие генерации на пинах `IN1` (PWM).
